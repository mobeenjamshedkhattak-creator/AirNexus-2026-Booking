BEFORE YOU START

Try the maps immediately.

  1. Extract the downloaded ZIP: right-click → Extract All.
  2. Open AirNexus-Editable-Portal.html in Chrome or Edge.
  3. Choose E-9 or H-11. Click a coloured area. Try changing its name, adding a room and booking an event.

STEP 01 / CREATE THE DATA STORE

Set up Supabase.

  1. Open Supabase Dashboard and sign in.
  2. Click New project. Select your organization.
  3. Project name: AirNexus Campus Atlas. Choose a strong database password and save it privately. This is not the password you will use to sign in to the portal.
  4. Choose a suitable nearby region. Create the project and wait until it is ready.
  5. In the left menu, open SQL Editor → New query.
  6. On your computer, find supabase/setup.sql inside the extracted project folder. Right-click → Open with → Notepad. Press Ctrl+A, then Ctrl+C.
  7. Go back to Supabase SQL Editor. Paste everything with Ctrl+V, then click Run.
  8. Look for a success message. This creates the two campus maps, rooms/events storage, organizer controls and save history.

Leave Row Level Security enabled. The SQL already sets the required permissions. You do not need to create separate tables by hand.
STEP 02 / CREATE YOUR PORTAL LOGIN

Create and approve your organizer account.

  1. In Supabase, open Authentication → Users.
  2. Click Add user → Create new user. Choose the creation option, rather than the invitation-email option.
  3. Enter the email you want to use and a strong password you will remember. Turn on Auto Confirm User if that option is shown. Create the user.
  4. On your computer, open supabase/add-organizer.sql in Notepad.
  5. Find REPLACE-WITH-YOUR-EMAIL@au.edu.pk and replace it with the exact email you just created. Keep the single quotation marks around the email.
  6. Copy the entire edited file into a new SQL Editor query. Click Run.
  7. Your email must appear in the result table. If it does not, check that you created the Auth user first and typed the same email.
YOUR TWO LOGIN DETAILS
Portal emailThe email from Authentication → Users
Portal passwordThe password you chose for that user
No default password is hidden in the files. You choose your own account. No custom SMTP is needed for this administrator-created password login.
How do I add another organizer?

Create another user under Authentication → Users. Change the email in add-organizer.sql to their email and run it again. Both organizers can access both campuses. If both edit the same campus together, revision checks prevent silent overwriting.

Should I turn off public signups?

On a project dedicated to AirNexus, you can open Authentication → Sign In / Providers and turn off “Allow new users to sign up.” Keep Email/password sign-in enabled. Do not change an existing project's signup settings if another application uses them. The organizer allowlist still blocks non-approved users from reading or saving maps.

STEP 03 / COPY ONLY TWO VALUES

Get the project URL and publishable key.

  1. In Supabase, open Project Settings. Find Data API for the project URL, or use the project's Connect dialog.
  2. Copy the Project URL. It looks like https://abcdef.supabase.co. Copy only the project URL, without /rest/v1.
  3. Open Project Settings → API Keys.
  4. Copy a Publishable key beginning with sb_publishable_. If no key is listed, create a publishable key on that page.
  5. Keep both values ready to paste into Vercel in Step 5.
What you copyExample onlyVercel variable name
Project URLhttps://abcdef.supabase.coSUPABASE_URL
Publishable keysb_publishable_…SUPABASE_PUBLISHABLE_KEY
Do not use a sb_secret_ key, service_role key, database password or organizer password here. The publishable key is meant for browser applications; the SQL access policies protect your data.
STEP 04 / UPLOAD THE APPLICATION

Put the project on GitHub.

  1. Open GitHub → New repository.
  2. Name it airnexus-campus-atlas. Choose Private. Create the repository.
  3. Click uploading an existing file, or Add file → Upload files.
  4. On your computer, open the extracted airnexus-campus folder. Select its contents and drag them into GitHub. Keep the folders named public, scripts, supabase, tests and docs intact.
  5. At the top level of the repository, you must see package.json, vercel.json, README.md and the folders above. Do not upload only the ZIP or only the HTML preview.
  6. Click Commit changes.

STEP 05 / GET YOUR WEBSITE LINK

Deploy on Vercel.

  1. Open Vercel → Add New → Project. Sign in with your GitHub account if prompted.
  2. Find airnexus-campus-atlas and click Import. If it is missing, allow Vercel to access that private repository.
  3. Framework Preset: choose Other.
  4. Root Directory: leave it at the repository root if package.json is there. If you uploaded a parent folder, choose the folder containing package.json.
  5. Build Command: npm run build. Output Directory: dist. Leave Install Command at its default. The included vercel.json normally supplies the build settings automatically.
  6. Expand Environment Variables. Add the two entries shown below. Paste your real values. Do not add quotation marks or spaces.
  7. Click Deploy. Wait for the Ready/success screen, then open the website URL ending in .vercel.app.
  8. Sign in with the organizer email and password from Step 2.

IF SOMETHING DOES NOT WORK

Easy fixes.

The Vercel website says “Local draft” instead of showing a login.

The build did not receive both environment variables. Add SUPABASE_URL and SUPABASE_PUBLISHABLE_KEY to the Vercel project, choose Production, then redeploy. Make sure you opened the actual Vercel URL, not the offline HTML file.

I get “Invalid login credentials.”

Check Authentication → Users for the account. Use that account's email and password, not the database password. Make sure the email is confirmed. If you forgot the password, reset it through your Supabase administrator tools; no password is provided in the source files.

It says organizer access or setup is missing.

Run the whole setup.sql file. Create your Auth user. In add-organizer.sql, replace the example email with the exact created email and run it. Your email must appear in the result. Sign in again.

The build rejects the key.

Use a publishable key beginning with sb_publishable_. Do not paste the secret key or database password. Copy the project URL without /rest/v1. If you only see legacy keys, use Settings → API Keys to create a publishable key.

Vercel cannot find package.json, index.html, or the build command.

Check GitHub's folder structure. package.json and vercel.json should be in the same root directory used by Vercel. Build command must be npm run build; output must be dist. Do not set output to public because the build also generates the Supabase configuration.

I cannot save, or other editors cannot see the changes.

Check the save indicator. If it says Local draft, you are using local mode. If it reports a connection problem, check that the Supabase project is running and has not been paused. If a revision conflict appears, back up the draft, then load the latest cloud plan.

The PDF or HTML did not download.

Prepare the file, then click its explicit Download button in the ready dialog. Use Chrome or Edge on the deployed HTTPS Vercel URL. Check the browser's download notifications. If your browser blocks downloads in an insecure local preview, use the deployed site rather than bypassing a security warning. SVG and JSON exports are also available.

How do I get edits from the offline HTML into the cloud?

Open the offline file → Export plan → Back up both campuses. Then sign in on the deployed portal → Export plan → Restore an AirNexus backup. Review the summary before replacing the cloud plans. Keep a cloud backup first.

Can students view the live portal without signing in?

This release is an organizer editing portal. Distribute PDF maps to students. The cloud plans are protected by organizer sign-in. The single-file HTML contains the exported data and does not require a password, so share it only with people who should see that copy.

Can I recover a deleted area?

Use Undo in the current session, or restore a JSON backup. Supabase also keeps the previous 30 saves per campus in an_revisions; an administrator can follow docs/TECHNICAL-NOTES.md for database recovery.
